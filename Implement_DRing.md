# Implementing a `DRing` in `dalgebra`

This note summarizes what must be implemented for a new ring in category `DRings`, and audits the current implementations in this repository.

## 1) Required methods from `DRings.ParentMethods`

These are the methods marked with `@abstract_method` in `dalgebra/dring.py`.

### `operators`

```python
def operators(self) -> Sequence[Morphism]:
    ...
```

- **Purpose**: return the ordered tuple/list of additive operators acting on `self`.
- **Return**: sequence of maps `self -> self`.

### `operator_types`

```python
def operator_types(self) -> tuple[str]:
    ...
```

- **Purpose**: classify each operator from `operators()`.
- **Return**: tuple with one entry per operator, each in `{"none", "homomorphism", "derivation", "skew"}`.

### `to_sage`

```python
def to_sage(self) -> Ring:
    ...
```

- **Purpose**: forget d-structure and return an equivalent Sage parent.
- **Return**: Sage parent/ring used as plain algebraic model.

### `linear_operator_ring`

```python
def linear_operator_ring(self) -> Ring:
    ...
```

- **Purpose**: build ring of linear operators generated by ring operators.
- **Return**: parent representing the operator ring.

### `constant_ring`

```python
def constant_ring(self, operation: int = 0) -> Parent:
    ...
```

- **Purpose**: compute constants for one chosen operator.
- **Return**: parent of constants (fixed elements for homomorphism, kernel for derivation/skew).

### `add_constants`

```python
def add_constants(self, *new_constants: str) -> Parent:
    ...
```

- **Purpose**: extend ring by new transcendental constants (constant for all operators).
- **Return**: new `DRing`-compatible parent with extended base.

### `_laurent_morphism`

```python
def _laurent_morphism(
    self,
    imgs: dict[str | Element, Element],
    constant: Parent = None
) -> MorphismToLaurent:
    ...
```

- **Purpose**: internal constructor used by public `laurent_morphism(...)`.
- **Return**: `MorphismToLaurent` from `self` to a Laurent-series codomain.

## 2) `DRings.ElementMethods` required implementation point

`DRings.ElementMethods` has no method decorated with `@abstract_method`, but one method is effectively abstract (raises `NotImplementedError` in base behavior):

### `conditions_to_zero`

```python
def conditions_to_zero(self) -> list[tuple[Element, Element]]:
    ...
```

- **Purpose**: return equations/conditions that are equivalent to element being zero.
- **Return**: list of `(equation, condition)`-style pairs used by higher-level algorithms.

## 3) Compliance audit of current DRing implementations

Audit scope: concrete DRing parents and their declared `Element` class.

### ✅ Fully implementing required parent + element methods

- `DRing_Wrapper` / `DRing_WrapperElement`
- `DPolynomialRing_Monoid` / `DPolynomial`
- `DMonomial_Parent` / `DMonomial_Element`
- `DElliptic_Field` / `DElliptic_Element`

### ⚠️ Missing required methods

#### `DFractionField` / `DFractionFieldElement`
- Missing in parent:
  - `linear_operator_ring`
- Missing in element:
  - _none_

#### `PseudoDOperator_Ring` / `PseudoDOperator`
- Missing in parent:
  - `constant_ring`
  - `to_sage`
- Missing in element:
  - `conditions_to_zero`

#### `PSeries_Ring` / `PSeries_Element`
- Missing in parent:
  - `constant_ring`
  - `to_sage`
- Missing in element:
  - `conditions_to_zero`

#### `LSeries_Ring` / `LSeries_Element`
- Missing in parent:
  - `constant_ring`
  - `to_sage`
- Missing in element:
  - `conditions_to_zero`
